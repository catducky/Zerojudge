# f608. 4. 飛黃騰達

- 題目：[ZeroJudge f608](https://zerojudge.tw/ShowProblem?problemid=f608)
- 程式：[main.cpp](main.cpp)
- 解法：排序＋最長非遞減子序列＋二分搜尋

## 題目重點

飛黃從原點出發，每次移動後的 x、y 都不能比原本小。求最多能經過多少個果實所在的位置。

因此，選到的點必須同時滿足 x 非遞減、y 非遞減。

## 解題思路

### 1. 先處理 x 的順序

將所有點按照 x 由小到大排序；如果 x 相同，則按照 y 由小到大排序。

因為題目允許 x 相同時繼續往上走，所以同一個 x 的點要依照 y 遞增排列，才可以依序選取。

排序後，x 已經符合條件，問題就變成：找出 y 序列的最長非遞減子序列長度。

### 2. 用更小的結尾保留接續機會

使用陣列 `lis`，讓 `lis[k]` 表示目前長度為 `k + 1` 的非遞減子序列，能達到的最小結尾值。

對每個 y，使用 `upper_bound` 找出第一個大於 y 的位置：

- 如果找不到，代表 y 大於或等於目前最長子序列的最小結尾，可以接在後面，加入 `lis`。
- 如果找到，就用 y 替換該位置，讓這個長度的子序列擁有更小的結尾，增加後續接上其他值的機會。

替換不會改變目前的答案長度，只是在保留更有利的結尾。

**注意：`lis` 是不同長度的最小結尾紀錄，本身不一定是一條實際選出的子序列。**

### 3. 為什麼是 upper_bound？

題目允許 y 相同，因此求的是「非遞減」，不是「嚴格遞增」。

例如 `(1, 2)`、`(2, 2)` 可以依序吃到，答案是 2。`upper_bound` 會略過相同值，讓第二個 2 接到後面；若改用 `lower_bound`，就會取代原本的 2，漏掉這種情況。

原程式中「y 比之前都大」的註解，更精確的說法是「y 大於或等於目前最長子序列的最小結尾」。程式保留原本 AC 版本。

## 範例追蹤

題目範例排序後為 `(1, 1)`、`(2, 5)`、`(3, 2)`，y 序列是 `1, 5, 2`。

| 目前 y | 操作 | lis |
| --- | --- | --- |
| 1 | 加入結尾 | `[1]` |
| 5 | 加入結尾 | `[1, 5]` |
| 2 | 用 2 取代 5 | `[1, 2]` |

最後長度為 2，因此輸出 2。

## 正確性說明

排序後，任一 y 非遞減子序列的 x 也必定非遞減，因此對應到合法的移動路線。反過來，合法路線中的點也會依照排序後的順序出現，因此只需要求出最長非遞減子序列。

處理每個 y 時，`upper_bound` 前面的結尾都小於或等於 y，因此可以接上 y。將第一個大於 y 的結尾換小，不會縮短已有的子序列，且對後續接續只會更有利。當找不到更大的結尾時，就能將最長長度延長一格。因此 `lis.size()` 就是最多能吃到的果實數量。

## 和 DP 的關係

可以先想到 O(n²) 的 DP：排序後，令 `dp[i]` 為以第 i 個點結尾時，最多能選到的點數。

對每個 `j < i`，若 `y[j] <= y[i]`，就能用 `dp[j] + 1` 更新 `dp[i]`；每個位置的初始值為 1。

這份程式用「每種長度的最小結尾」搭配二分搜尋，把求最長非遞減子序列的時間降到 O(n log n)，因此也可以視為 LIS 類 DP 的最佳化做法。

## 複雜度

- 時間：O(n log n)，包含排序與 n 次二分搜尋。
- 空間：O(n)，用來存放座標與 `lis`。
